Live endpoint · no API key required

Free neural text-to-speech,
on the OpenAI API shape.

Point any OpenAI-compatible client at this domain and get ~320 neural voices back, with no key and no billing. The same project runs locally as a CLI that turns Markdown into chaptered audiobooks with word-accurate subtitles.

Use it from your own code

  
curl -s https://example.netlify.app/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"model":"tts-1","input":"Hello from the edge.","voice":"nova"}' \
  --output hello.mp3


  
from openai import OpenAI

client = OpenAI(base_url="https://example.netlify.app/v1", api_key="anything")
client.audio.speech.create(
    model="tts-1", voice="onyx", input="Verified against the official SDK."
).write_to_file("out.mp3")


  

    All eleven OpenAI voice names work (alloy, ash, ballad,
    coral, echo, fable, nova, onyx,
    sage, shimmer, verse), so do short aliases like
    jenny and sonia, and so does any native name such as
    en-AU-NatashaNeural — unrecognised names pass straight through to the engine.
  


  

    

      
EndpointNotes

      
        
POST /v1/audio/speechOpenAI-compatible. Returns audio/mpeg.

        
POST /v1/audio/subtitlesttskit extension: base64 audio + .srt + .vtt + per-word marks.

        
GET /v1/voicesFull catalogue plus the alias table.

        
GET /v1/modelsFor clients that probe before calling.

        
GET /healthzEngine, formats and limits.

      
    

  


  

    What the hosted endpoint won't do. Serverless functions have no ffmpeg, so
    this returns mp3 only, and requests are capped at 5,000 characters with a
    ~10 second execution limit. Long-form work — audiobooks, chapters, ID3 tags,
    opus/aac/flac, offline voices — is what the local CLI is for.
  


  
Run the full toolkit locally

  
git clone https://github.com/skyar123/Speech-to-text-.git
cd Speech-to-text-
pip install -e ".[server,ffmpeg]"

ttskit book notes.md -o notes.mp3 --subs srt   # chaptered audiobook + captions
ttskit serve                                    # this same API on :5050
ttskit watch ~/claude-output --out ~/audio      # narrate files as they land


  

    

      
Audiobooks

      
Markdown, PDF, HTML or a URL becomes one tagged MP3 or a chaptered M4B. Code fences and
      link URLs are stripped; headings become chapters.

    

    

      
Real subtitles

      
The engine reports the millisecond each word begins. Those marks are shifted onto the
      stitched timeline, so captions stay in sync across a whole book.

    

    

      
Offline voices

      
Kokoro-82M runs on CPU through ONNX Runtime. Nothing leaves the machine — useful when
      the text shouldn't.

    

    

      
No ffmpeg needed

      
MP3 stitching, paragraph silence and chapter offsets are pure Python. ffmpeg is only
      for opus/aac/flac and M4B chapters.
